# Task04: Reproducible rover bringup

Домашнее задание выполняется в `task04/` вашего личного приватного репозитория.
Начните с [условия и критериев оценивания](docs/Homework_L04.md); интерфейсы,
допуски и параметры описаны в [контракте](docs/CONTRACT.md).

Среда: Docker, Ubuntu 24.04, ROS 2 Jazzy, Gazebo Harmonic. ROS на хосте
устанавливать не нужно. Двухколёсная платформа Task04 независима от Task03.

## Подготовка среды

Все команды ниже выполняются из `task04/` личного репозитория.

```bash
cp .env.example .env
```

На Linux и в WSL установите в `.env` значения `LOCAL_UID` и `LOCAL_GID`,
которые показывают `id -u` и `id -g`. На macOS с Docker Desktop обычно
подходят значения 1000. Не добавляйте локальный `.env` в commit.

```bash
./course up
./course doctor
./course build
```

Первый запуск собирает образ и скачивает зависимости. `doctor` проверяет
пакеты, rendering и возможность записи в workspace. Если он сообщает об
ошибке доступа, исправьте UID/GID и пересоздайте контейнер командами
`./course down` и `./course up`. Каталог репозитория должен принадлежать
вашему пользователю; не запускайте сборку через `sudo`.

## Выполнение и проверка

Заполните три файла из [условия](docs/Homework_L04.md), добавьте собственный
тест и объяснение. До заполнения TODO запуск сообщает о незавершённой
конфигурации, а тесты анализатора падают; это ожидаемое состояние starter.
Успешная сборка сама по себе не подтверждает решение.

```bash
./course build
./course test
./course check --output evidence/homework-check.json
```

`check` самостоятельно поднимает свежий headless стенд и завершает его.
Перед проверкой остановите другие launch этого задания. `observe` и
`scenario` работают с уже запущенной сценой. По умолчанию все команды
используют домашнюю сцену. Одновременно используйте один запуск в одном
ROS domain и Gazebo partition.

Для интерактивного просмотра после заполнения конфигурации:

```bash
./course homework
```

Во втором терминале, также из `task04/`, выполните `./course desktop` и
откройте напечатанный адрес. Порядок опытов и команды для seed, RTF и
noise profiles приведены в [условии](docs/Homework_L04.md).

## Сдача

Сохраните решение, собственный тест, выбранные evidence и `docs/diagnosis.yaml`
в `task04/`. Каталог `evidence/` игнорируется Git; добавьте нужные небольшие
JSON-отчёты явно, как описано в условии. Сделайте commit и push в `master`
личного приватного репозитория до объявленного преподавателем дедлайна.
Команды сдачи из корня репозитория приведены в [общем README](../README.md).

## Завершение и помощь

Остановите запущенный launch через Ctrl+C, затем выполните `./course down`.
При ошибке сохраните полный вывод, результат `./course doctor`, версию
Docker и точную команду запуска.

```bash
./course exec ros2 topic list -t
./course exec gz topic -l
docker compose logs --tail=100 workspace
```

Камера и LiDAR используют графический движок даже без окон. Образ
настраивает software rendering; фактический RTF зависит от компьютера.
Вывод `check` и сохранённый log помогают отличить проблему окружения от
ошибки решения.
